## 升级概述

FileShare 系统采用版本化升级机制，每个版本更新都提供独立的升级脚本，确保升级过程安全可靠。

### 版本号规则

系统版本号遵循语义化版本规范（Semantic Versioning）：
- **主版本号**（Major）：不兼容的 API 修改
- **次版本号**（Minor）：向下兼容的功能性新增
- **修订号**（Patch）：向下兼容的问题修正

例如：`1.0.1` 表示主版本 1，次版本 0，修订号 1。

### 升级脚本位置

所有升级脚本位于 `upgrades/` 目录：
```
upgrades/
├── README.md                    # 升级脚本说明
├── version.json                 # 版本管理文件
├── upgrade-v1.0.0-to-v1.0.1.js # 升级脚本
└── ...
```

## 升级前准备

### 1. 检查当前版本

运行以下命令查看当前版本：

```bash
npm run check-version
```

或直接查看版本文件：

```bash
cat upgrades/version.json
```

### 2. 备份数据

**⚠️ 重要：升级前必须备份数据！**

#### 备份数据库

```bash
# 方式一：使用管理后台备份（推荐）
# 进入 系统管理 > 数据备份 > 立即备份

# 方式二：使用命令行备份
npm run backup

# 方式三：手动备份
cp data/fileshare.db data/fileshare.db.backup.$(date +%Y%m%d_%H%M%S)
```

#### 备份存储文件

```bash
# 备份整个 storage 目录
cp -r storage storage.backup.$(date +%Y%m%d_%H%M%S)
```

#### 备份配置文件

```bash
# 备份环境变量文件
cp .env .env.backup.$(date +%Y%m%d_%H%M%S)
```

### 3. 停止系统服务

升级前必须停止所有系统服务：

**Linux/Unix**：
```bash
# 查找并停止 Node.js 进程
ps aux | grep node
pkill -f "node server/index.js"
pkill -f "vite"
```

**Windows**：
```powershell
# 查找并停止 Node.js 进程
Get-Process | Where-Object {$_.ProcessName -like "*node*"}
Stop-Process -Name node
```

**使用 PM2（如果使用）**：
```bash
pm2 stop all
```

### 4. 查看升级说明

在运行升级脚本前，请查看：
- 升级脚本中的更新内容说明
- 版本发布说明（如果有）
- 操作文档中的升级章节

## 执行升级

### 方式一：使用 npm 脚本（推荐）

```bash
npm run upgrade
```

### 方式二：直接运行升级脚本

```bash
# 从 v1.0.0 升级到 v1.0.1
node upgrades/upgrade-v1.0.0-to-v1.0.1.js
```

### 升级过程说明

升级脚本会自动执行以下步骤：

1. **检查版本**：验证当前版本是否符合升级要求
2. **备份数据库**：自动备份数据库文件
3. **验证文件**：检查升级所需的文件是否存在
4. **执行升级**：执行升级操作（代码更新、数据库迁移等）
5. **更新版本号**：更新版本管理文件
6. **验证结果**：验证升级是否成功

### 升级输出示例

```
========================================
  FileShare 系统升级脚本
  从 v1.0.0 升级到 v1.0.1
========================================

[步骤 1] 备份数据库
✓ 数据库已备份到: data/fileshare.db.backup.1234567890

[步骤 2] 验证升级文件
✓ 文件存在: client/src/components/FilePreview.tsx
✓ 文件存在: server/routes/files.js
✓ 所有升级文件验证通过

[步骤 3] 执行升级操作
✓ 代码更新已完成（通过 Git 拉取或手动更新）

[步骤 4] 更新版本号
✓ 版本已更新: 1.0.0 -> 1.0.1

[步骤 5] 验证升级结果
✓ 升级成功！当前版本: 1.0.1

========================================
  升级完成！
========================================
```

### 获取升级文件

升级脚本会验证文件是否存在，但不会自动更新代码。您需要：

**方式一：从 Git 仓库更新（推荐）**
```bash
git pull origin main
# 或切换到指定版本
git checkout v1.0.1
```

**方式二：手动下载升级包**
1. 从发布页面下载升级包
2. 解压并覆盖相应文件
3. 确保文件权限正确

## 升级后验证

### 1. 检查版本号

```bash
npm run check-version
```

应该显示新的版本号。

### 2. 重启服务

**开发环境**：
```bash
npm run dev
```

**生产环境**：
```bash
# 启动后端
npm run server:start

# 构建前端（如需要）
npm run client:build
```

### 3. 功能验证

验证以下功能是否正常：

- [ ] 系统正常启动
- [ ] 用户登录功能
- [ ] 文件上传/下载
- [ ] 文件预览功能
- [ ] 空间管理功能
- [ ] 权限控制功能
- [ ] 新功能（查看更新说明）

### 4. 检查日志

查看系统日志，确认没有错误：

```bash
# 查看服务器日志
tail -f logs/server.log

# 或查看控制台输出
```

## 回滚操作

如果升级后出现问题，可以回滚到旧版本：

### 1. 停止服务

```bash
# 停止所有服务
pkill -f node
# 或
pm2 stop all
```

### 2. 恢复数据库

```bash
# 找到备份文件
ls -la data/fileshare.db.backup.*

# 恢复数据库
cp data/fileshare.db.backup.1234567890 data/fileshare.db
```

### 3. 恢复代码

```bash
# 使用 Git 回滚
git checkout v1.0.0

# 或手动恢复文件
```

### 4. 恢复版本号

编辑 `upgrades/version.json`，将版本改回旧版本：

```json
{
  "currentVersion": "1.0.0",
  ...
}
```

### 5. 重启服务

```bash
npm run server:start
```

## 常见问题

### Q1: 升级脚本执行失败怎么办？

**A**: 
1. 查看错误信息，确定失败原因
2. 检查备份文件是否完整
3. 确认文件权限是否正确
4. 尝试手动执行升级步骤
5. 联系技术支持

### Q2: 可以跳过版本升级吗？

**A**: 不建议跳过版本升级。每个升级脚本都针对特定版本设计，跳过可能导致：
- 数据库结构不匹配
- 功能异常
- 系统不稳定

### Q3: 升级需要多长时间？

**A**: 通常几分钟内完成，具体时间取决于：
- 数据库大小
- 文件数量
- 网络速度（如果从远程拉取代码）
- 升级操作的复杂度

### Q4: 升级会影响现有数据吗？

**A**: 
- 升级脚本会自动备份数据库
- 正常情况下不会影响现有数据
- 但建议升级前手动备份重要数据
- 如果升级包含数据库迁移，可能会修改数据结构

### Q5: 如何查看升级历史？

**A**: 查看 `upgrades/version.json` 文件中的 `upgradeHistory` 字段：

```bash
cat upgrades/version.json | grep -A 10 upgradeHistory
```

### Q6: 升级后需要重新安装依赖吗？

**A**: 
- 如果 `package.json` 中的依赖没有变化，不需要
- 如果依赖有更新，运行：
  ```bash
  npm install
  cd client && npm install && cd ..
  ```

### Q7: 升级脚本支持哪些操作系统？

**A**: 升级脚本使用 Node.js 编写，支持：
- Linux
- macOS
- Windows（需要 Git Bash 或 PowerShell）
